# 收款渠道接入 · 方案索引

本仓库产品为 **Payments**（多收款账号与交易流水）。当前落地渠道为 **PayPal**；下列方案均针对 PayPal 查订单。其它渠道（Stripe 等）将按同一「账号 → 凭证 → 同步流水」模型另立文档。

五种官方做法都需要至少一个 PayPal App。不创建应用、也不提供 Client ID 和 Secret，PayPal 不会发 access token。商家的邮箱和密码也不能换成 API token。

本目录每种方案一份实施文档。当前仓库只实现了第一种，并在沙箱跑通。管理台「运营登录 + 商家 PayPal 授权」的时序与 Mermaid 图见 [授权流程图.md](授权流程图.md)。

| --- | --- | --- | --- | --- |
| 商家登录授权 | [01-商家登录授权.md](01-商家登录授权.md) · [授权流程图.md](授权流程图.md) | 平台 App 换出的商家 access token 和 refresh token | 点登录并同意，不创建 App | 已实现，沙箱已查到订单 |

## 怎么选

- 商家不愿意自己建 App，平台也还不是 PayPal 合作伙伴：用 [01-商家登录授权.md](01-商家登录授权.md)。Client ID 和 Secret 来自平台创建的那一个普通 REST App，商家只登录授权。创建这个 App 不需要合作伙伴资格。这是当前演示。
- 软件装在商家自己的服务器上，希望 PayPal 给每个商家发一套 REST 凭证：用 [02-合作伙伴签发商家凭证.md](02-合作伙伴签发商家凭证.md)。这是 `FIRST_PARTY`，不支持平台费和延迟打款。
- 平台是托管 SaaS，要替很多商家查订单、收款或收平台费：用 [03-平台令牌与Auth-Assertion.md](03-平台令牌与Auth-Assertion.md)。这是 `THIRD_PARTY`。
- 每个商家都能自己建 App，并愿意把 Secret 交给平台：用 [04-商家自建应用.md](04-商家自建应用.md)。
- 只需要知道「刚刚支付成功或退款」，不需要按订单号回查历史：用 [05-Webhook支付通知.md](05-Webhook支付通知.md)。它可以和前四种同时使用，但不能单独代替查订单。
沙箱和 Live 的 App、账号、订单号、Webhook 地址不能混用。
