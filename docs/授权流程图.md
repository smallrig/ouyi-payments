# 授权流程图

本文描述 **Payments 管理台** 里两套独立授权如何衔接，并给出可在 Markdown 预览中渲染的 Mermaid 图。选型说明见 [实施方案.md](实施方案.md)；PayPal「商家登录授权」细节见 [01-商家登录授权.md](01-商家登录授权.md)。

---

## 0. 两套授权（先分清）

| 层级 | 谁登录 | 凭证 | 用途 |
| --- | --- | --- | --- |
| **管理台登录** | 运营人员 | 本服务签发的 **JWT**（`ADMIN_USERNAME` / `ADMIN_PASSWORD`） | 访问 `/api/accounts`、`/api/disputes` 等业务接口 |
| **商家 PayPal 授权** | 商家 PayPal 账号 | 平台 App 换出的 **商家 access_token + refresh_token** | 代该商家调 PayPal Orders / Transaction Search / Disputes |

两者不能互换：JWT 进不了 PayPal；商家 token 也不能当管理台登录态。

```mermaid
flowchart LR
  subgraph Admin["管理台登录"]
    A1[运营人员] --> A2[POST /api/auth/login]
    A2 --> A3[(JWT)]
    A3 --> A4[Bearer 调业务 API]
  end

  subgraph Merchant["商家 PayPal 授权"]
    B1[运营人员点「授权」] --> B2[GET /api/auth/start]
    B2 --> B3[PayPal 登录同意]
    B3 --> B4[GET /api/callback]
    B4 --> B5[(商家 refresh_token 入库)]
    B5 --> B6[Bearer 商家 token 调 PayPal]
  end

  A4 -.->|业务接口内部| B6
```

## 1. 总览：从打开页面到能查交易

```mermaid
flowchart TB
  Start([打开管理台]) --> Login{已有有效 JWT?}
  Login -->|否| LocalLogin[登录页 POST /api/auth/login]
  LocalLogin --> StoreJWT[前端存 JWT]
  Login -->|是| Accounts[账号列表 /accounts]
  StoreJWT --> Accounts

  Accounts --> NeedAuth{目标商家已授权?<br/>库中有 refresh_token}
  NeedAuth -->|是| Sync[同步交易 / 查争议]
  NeedAuth -->|否| OAuthUI[点「使用 PayPal 授权」]

  OAuthUI --> Modal[过渡弹框 ~900ms]
  Modal --> StartOAuth[浏览器跳转 GET /api/auth/start]
  StartOAuth --> PP[PayPal /connect 同意页]
  PP -->|同意| CB[GET /api/callback?code&state]
  PP -->|拒绝| ErrCB[callback?error=...]
  CB --> Exchange[code 换 token + userinfo]
  Exchange --> Upsert[(upsert pp_paypal_account)]
  Upsert --> RedirectOK[302 → 前端 /accounts?auth=ok]
  ErrCB --> RedirectErr[302 → /accounts?auth=error&detail=...]
  RedirectOK --> Sync
```

## 2. 管理台登录时序

对应：`payments-admin-service` → `LocalAuthController`；前端 `store/auth` + `POST /api/auth/login`。

```mermaid
sequenceDiagram
  autonumber
  actor User as 运营人员
  participant Web as payments/web
  participant API as payments-admin-service
  participant Guard as AuthGuard

  User->>Web: 输入账号密码
  Web->>API: POST /api/auth/login<br/>{ username, password }
  Note over API: 与 ADMIN_USERNAME / ADMIN_PASSWORD<br/>做 timing-safe 比对
  alt 校验失败
    API-->>Web: 401 账号或密码错误
  else 校验成功
    API-->>Web: { token, user }
    Web->>Web: 持久化 JWT
  end

  User->>Web: 访问业务页
  Web->>API: GET /api/accounts<br/>Authorization: Bearer JWT
  API->>Guard: 校验 JWT_SECRET / exp
  alt JWT 无效
    Guard-->>Web: 401
  else 通过
    API-->>Web: 账号列表（不含令牌原文）
  end
```

说明：

- `/api/auth/login`、`/api/auth/start`、`/api/callback` 标了 `@Public()`，不强制 JWT。
- PayPal 授权跳转是**整页导航**，不带 `Authorization` 头；OAuth 会话靠 **HttpOnly Cookie**（见下节）。

## 3. 商家 PayPal 授权（主流程）

对应：前端 `lib/oauth.ts` → `OauthController` → `PaypalClient.exchangeAuthorizationCode` → `AccountService.upsert`。

### 3.1 时序图

```mermaid
sequenceDiagram
  autonumber
  actor Op as 运营人员
  participant Web as 管理台前端
  participant API as OauthController
  participant Sess as OauthSessionService<br/>(pp_oauth_session)
  participant PP as PayPal
  participant Acc as AccountService<br/>(账号表)

  Op->>Web: 点击「授权」<br/>可选带 accountId=payerId
  Web->>Web: 展示 PpOAuthRedirectModal
  Web->>API: GET /api/auth/start?accountId=...

  API->>API: assertCredentials()
  API->>Sess: 读 Cookie 会话；无则 start() 并 Set-Cookie
  Note over Sess: Cookie: OAUTH_COOKIE_NAME<br/>HttpOnly; SameSite=Lax; Path=/
  API->>Sess: 写入 oauth.state / nonce / expiresAt / linkPayerId
  API-->>Web: 302 → PayPal 授权 URL

  Web->>PP: 打开 /connect?...&state&nonce&scope&redirect_uri
  Op->>PP: 用商家账号登录并同意

  alt 商家同意
    PP-->>API: 302 GET /api/callback?code&state
  else 商家拒绝
    PP-->>API: 302 GET /api/callback?error&error_description
  end

  API->>Sess: 用 Cookie 读会话，核对 state 且未过期
  API->>Sess: 立刻清除 session.oauth（一次性）

  alt state 失败 / 过期 / 无 code / 有 error
    API-->>Web: 302 FRONTEND_URL/accounts?auth=error&detail=...
  else 正常
    API->>PP: POST /v1/oauth2/token<br/>grant_type=authorization_code
    Note over API,PP: Basic(client_id:secret)<br/>redirect_uri 须与授权时一致
    PP-->>API: access_token, refresh_token, scope, expires_in
    API->>PP: GET userinfo?schema=paypalv1.1
    PP-->>API: payer_id, email, name
    API->>Acc: upsert 商家账号<br/>status→active（或保留 frozen）
    API-->>Web: 302 FRONTEND_URL/accounts?auth=ok
  end
```

### 3.2 关键节点（与代码一一对应）

```mermaid
flowchart TD
  A["GET /api/auth/start"] --> B{有 OAuth Cookie 会话?}
  B -->|否| C["生成 session id + Set-Cookie"]
  B -->|是| D["复用会话"]
  C --> E["写入 state/nonce/expiresAt/linkPayerId"]
  D --> E
  E --> F["302 PayPal buildAuthorizeUrl"]

  F --> G["商家在 PayPal 同意/拒绝"]
  G --> H["GET /api/callback"]

  H --> I{Cookie 会话存在<br/>且 state 匹配<br/>且 oauth.expiresAt 未过期?}
  I -->|否| X["前端 ?auth=error state 校验失败"]
  I -->|是| J["删除 session.oauth 并 save"]

  J --> K{query.error?}
  K -->|是| X2["?auth=error&detail=拒绝原因"]
  K -->|否| L{有 code?}
  L -->|否| X3["?auth=error 无 authorization code"]
  L -->|是| M["exchangeAuthorizationCode"]

  M --> N["requestToken authorization_code"]
  N --> O["fetchUserInfo"]
  O --> P{payer_id 或 linkPayerId?}
  P -->|都没有| X4["502 无法取得 payer_id"]
  P -->|有| Q{有 refresh_token?}
  Q -->|否| X5["502 缺少 refresh_token<br/>检查 openid scope"]
  Q -->|是| R["accounts.upsert"]
  R --> S["302 ?auth=ok"]
```

### 3.3 重新授权（带 `accountId`）

当 userinfo 偶发拿不到 `payer_id`，或运营人员从「某账号详情」发起授权时：

1. 前端：`startPayPalOAuth(payerId)` → `/api/auth/start?accountId={payerId}`
2. 服务端把 `accountId` 存进会话的 `linkPayerId`
3. 换码后：`payerId = userinfo.payer_id || linkPayerId`
4. 有 `linkPayerId` 时可回绑原账号行，避免 profile 失败导致「幽灵新账号」

```mermaid
flowchart LR
  Detail[账号详情页未授权] -->|accountId=RMY...| Start[/auth/start]
  Start --> Sess[(oauth.linkPayerId)]
  Sess --> Callback[/callback]
  Callback --> Merge{userinfo.payer_id?}
  Merge -->|有| UsePP[用 PayPal payer_id]
  Merge -->|无| UseLink[用 linkPayerId 回绑]
  UsePP --> DB[(upsert 同一 payerId)]
  UseLink --> DB
```

## 4. 授权后：业务调用如何用商家令牌

管理台请求只带 **JWT**；服务端内部再换成 **商家 access_token** 调 PayPal。

```mermaid
sequenceDiagram
  autonumber
  participant Web as 管理台
  participant API as 业务 Controller
  participant Client as PaypalClient
  participant DB as 账号表
  participant PP as PayPal API

  Web->>API: POST /api/accounts/{payerId}/sync-transactions<br/>Authorization: Bearer JWT
  API->>Client: searchTransactions(payerId)
  Client->>DB: findOne(payerId)
  alt 无 refresh_token
    Client-->>API: 401 尚未授权
  else access_token 仍有效<br/>expiresAt - now > TOKEN_REFRESH_SKEW
    Client->>PP: GET /v1/reporting/transactions<br/>Bearer 商家 access_token
  else 需刷新
    Note over Client: 同 payerId 并发共用 merchantFlights
    Client->>PP: POST /v1/oauth2/token<br/>grant_type=refresh_token
    PP-->>Client: 新 access_token（可能带新 refresh_token）
    Client->>DB: upsert 令牌字段
    Client->>PP: GET ...transactions
  end
  PP-->>Client: 交易 JSON
  Client-->>API: 结果
  API-->>Web: 同步结果 / 列表
```

解除授权：`DELETE /api/accounts/{payerId}` → `AccountService.clearTokens`，清空令牌并把 `active` 改回 `pending`，之后必须重新走第 3 节流程。

## 5. 部署拓扑与 URL 对齐

沙箱示例（正式把 host / 凭证换成 Live 即可，**禁止混用**）：

| 配置 | 含义 | 示例 |
| --- | --- | --- |
| 前端 | `FRONTEND_URL` / CORS | `https://payments-sandbox.ouyishop.com` |
| API | Nginx 反代到 Nest | `https://payments-sandbox-api.ouyishop.com` |
| OAuth 入口 | `VITE_PAYPAL_OAUTH_START` | `…/api/auth/start` |
| Return URL | `PAYPAL_REDIRECT_URI` **且** App Dashboard Return URL | `…/api/callback` |
| 授权页 | sandbox / live | `www.sandbox.paypal.com/connect` 或 `www.paypal.com/connect` |
| Token API | sandbox / live | `api-m.sandbox.paypal.com` 或 `api-m.paypal.com` |

```mermaid
flowchart LR
  Browser[浏览器]
  FE[管理台静态站]
  API[payments-admin-service]
  PPW[PayPal Web]
  PPA[PayPal API]

  Browser -->|同源或 CORS| FE
  Browser -->|JWT API| API
  Browser -->|整页跳转 OAuth| API
  API -->|302| PPW
  PPW -->|302 code| API
  API -->|换 token / 查单| PPA
  API -->|完成后 302| FE
```

**必须逐字一致：**

1. `PAYPAL_REDIRECT_URI` ≡ Developer Dashboard 的 Return URL ≡ 授权请求里的 `redirect_uri` ≡ 换 token 时的 `redirect_uri`
2. `PAYPAL_CLIENT_ID` / `SECRET` 与 `PAYPAL_ENV`（sandbox|live）匹配
3. Live 需 App 已开通 Log in with PayPal，且所需 scope（交易、争议等）已批准；否则会出现 `invalid_client` / `invalid_scope`

## 6. 异常路径速查

```mermaid
flowchart TB
  E1[invalid_client] --> F1[凭证错误或沙箱/Live 混用]
  E2[redirect_uri 相关错误] --> F2[Return URL 未保存/未生效/多字符差异]
  E3[invalid_scope] --> F3[Live App 功能未开或 Pending]
  E4[invalid_grant] --> F4[code 过期/已用，或换码 redirect_uri 不一致]
  E5[state 校验失败] --> F5[Cookie 丢失、跨站拦 Cookie、超时、伪造回调]
  E6[无 refresh_token] --> F6[scope 缺 openid，或 App 未开 LiWP]
  E7[业务 401 尚未授权] --> F7[未授权或已 revoke，重新 /auth/start]
```

回调失败时用户看到：`/accounts?auth=error&detail=…`（detail 截断约 300 字符）。成功：`/accounts?auth=ok`；若 userinfo 有非致命错误会带 `&profile=…`。
