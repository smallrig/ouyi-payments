# 方案一：商家登录授权

平台自己创建一次 App，Client ID 和 Secret 都来自这一个 App。商家不创建 App，只点「使用 PayPal 登录并授权」。服务端用授权码换成该商家的 access token。之后查订单只带这张 token。

「平台还不是 PayPal 合作伙伴」指的是还没有合作伙伴资格。方案二、方案三才需要这个资格。任何开发者账号都能在 Dashboard 建一个普通 REST App，并打开 Log in with PayPal。这和合作伙伴入驻是两件事。

本仓库已经按本文实现，并在沙箱查到订单 `10398217929679849`，状态 `CREATED`，金额 `1.00 USD`。该请求没有带 `PayPal-Auth-Assertion`。授权商家的 payer_id 为 `RMY6DU53LZ2LQ`。

选型见 [实施方案.md](实施方案.md)。管理台实际跳转、Cookie / state、双层登录与令牌刷新见 [授权流程图.md](授权流程图.md)。

## 1. 角色

- **平台**：本系统。拥有一个 PayPal REST App。Client ID、Secret 只存在服务端。
- **商家**：被查询订单的 PayPal 账户。用自己的账号登录并同意。不能使用创建该 App 的同一个 PayPal 账户给自己授权。
- **买家**：订单里的付款人。不参与这次授权。

## 2. 调用关系

```text
商家浏览器
  │  1. 打开「使用 PayPal 登录并授权」
  ▼
本系统 /auth/start
  │  2. 生成 state，302 到 PayPal 授权页
  ▼
PayPal 登录并同意
  │  3. 302 回 /callback?code=...&state=...
  ▼
本系统（服务端）
  │  4. 用平台 Client ID + Secret 把 code 换成 access_token、refresh_token
  │  5. 用 access_token 读商家资料，加密保存 refresh_token
  ▼
之后所有订单请求
  │  6. Authorization: Bearer {商家 access_token}
  ▼
PayPal Orders / Transaction Search
```

查订单、列最近交易、创建测试订单，都不再附带 Client ID 或 Secret。

## 3. 平台一次性准备

在 [PayPal Developer Dashboard](https://developer.paypal.com/dashboard/applications) 的 Sandbox 创建一个 App。Live 上线时在 Live 环境另建一套。两套凭证不能混用。

1. 打开 Log in with PayPal。
2. Return URL 与服务端配置逐字相同。本地是 `http://127.0.0.1:3000/callback`。生产必须是 `https`。PayPal 提示 Return URL 变更最长可能数小时生效；本次沙箱修改后立即生效，上线时仍要预留时间。
3. 在 Log in with PayPal 高级设置中勾选 Full name、Email、PayPal account ID（payer ID）。
4. 要查询订单和最近交易时，在 App 权限里打开 Payments 和 Transaction Search。最终以 token 响应里的 `scope` 为准。本次沙箱 token 已包含 `payments/payment/authcapture`、`payments/refund` 和 `reporting/search/read`。

```text
PAYPAL_ENV=sandbox
PAYPAL_CLIENT_ID=
PAYPAL_CLIENT_SECRET=
PAYPAL_REDIRECT_URI=http://127.0.0.1:3000/callback
PORT=3000
PAYPAL_AUTHORIZE_STYLE=connect
PAYPAL_SCOPES=openid profile email https://uri.paypal.com/services/paypalattributes
```

本仓库对应文件：

| 文件 | 职责 |
| --- | --- |
| `src/server.js` | `/auth/start`、`/callback`、查询订单、列交易、创建测试订单 |
| `src/paypal.js` | 拼授权地址、换 token、刷新 token、调用 PayPal |
| `src/store.js` | 把商家 refresh token 写到本机 `data/merchant-token.json` |
| `public/index.html`、`public/app.js` | 一个授权按钮；登录后查订单和最近交易 |

## 4. 发起授权

`GET /auth/start`

1. 生成 `state` 和 `nonce`，放进服务端会话。Cookie 为 HttpOnly，`SameSite=Lax`，从 PayPal 跳回时仍会带上。
2. `state` 有效期 10 分钟，回调时核对并立即作废。
3. 302 到沙箱授权地址：

```text
https://www.sandbox.paypal.com/connect?flowEntry=static
  &client_id={平台 Client ID}
  &response_type=code
  &scope=openid profile email https://uri.paypal.com/services/paypalattributes
  &redirect_uri={与 App Return URL 完全相同}
  &state={随机串}
  &nonce={随机串}
```

生产主机换成 `https://www.paypal.com`。旧入口 `/signin/authorize` 仍可用，本方案默认 `/connect`。

同意后 PayPal 回到：

```text
{redirect_uri}?code={authorization_code}&state={原样带回的 state}
```

商家拒绝时回来的是 `error` 和 `error_description`，没有 `code`。

## 5. 立刻用授权码换 token

授权码大约 3 分钟内有效，只能使用一次。必须在 `/callback` 里由服务端马上兑换。

```http
POST https://api-m.sandbox.paypal.com/v1/oauth2/token
Authorization: Basic {Base64(client_id:client_secret)}
Content-Type: application/x-www-form-urlencoded
Accept: application/json

grant_type=authorization_code&code={code}&redirect_uri={与授权请求相同}
```

生产主机是 `https://api-m.paypal.com`。

| 字段 | 用法 |
| --- | --- |
| `access_token` | 之后调用订单 API。约 28800 秒（8 小时）过期 |
| `refresh_token` | 只保存在服务端，用来换新的 access token |
| `token_type` | `Bearer` |
| `expires_in` | 可能是数字或字符串，按数字解析 |
| `scope` | 这张 token 实际被授予的权限 |
| `nonce` | PayPal 自己生成的值，不是授权链接里那个 `nonce`。不要拿两者比对，否则会误判并丢掉本可使用的 token |

| PayPal 结果 | 处理 |
| --- | --- |
| `client_id或redirect_uri无效` | Return URL 未保存、未生效，或和请求差一个字符。`localhost` 与 `127.0.0.1`、端口、http/https 都算不同 |
| `invalid_client` | Client ID 或 Secret 错误，或沙箱凭证打到了生产地址 |
| `invalid_grant` | 授权码过期、已用过，或换 token 时的 `redirect_uri` 与授权时不一致 |
| state 不一致 | 会话丢失、Cookie 被拦，或回调被伪造。让商家重新点授权 |

接着读身份：

```http
GET https://api-m.sandbox.paypal.com/v1/identity/oauth2/userinfo?schema=paypalv1.1
Authorization: Bearer {access_token}
```

scope 含 `paypalattributes` 时，响应里有 `payer_id`。同时保存 `email` 和 `name`。`payer_id` 是稳定标识。这一步失败时，token 仍然保存，订单查询可以继续。

## 6. 保存和刷新

每个商家一条记录，键是 `payer_id`：`email`、`name`、`access_token`、加密后的 `refresh_token`、`scope`、`expires_at`。

演示把单商家记录写在 `data/merchant-token.json`，权限 `600`，已被 git 忽略。生产改为数据库加密存储。access token 可只放缓存。页面只显示姓名、邮箱、payer_id 和剩余秒数。

剩余不足 60 秒时先刷新，同一商家并发只刷新一次：

```http
POST /v1/oauth2/token
Authorization: Basic {Base64(client_id:client_secret)}
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token&refresh_token={refresh_token}
```

响应里若有新的 `refresh_token`，立刻覆盖。商家取消授权后刷新会失败，删除本地记录并要求重新登录。改过 App 权限后，旧 token 可能数小时内仍是旧 scope，需要新权限时让商家重新同意。

## 7. 查订单

以下请求只带 `Authorization: Bearer {商家 access_token}`。不要再送 Client ID、Secret 或 `PayPal-Auth-Assertion`。

按订单号：

```http
GET /v2/checkout/orders/{order_id}
Authorization: Bearer {access_token}
Accept: application/json
Accept-Language: en_US
```

Orders v2 不能列出一个账户的全部订单。`order_id` 只允许 1 到 36 位大写字母和数字。不要默认加 `fields=payment_source`。对还没有付款来源的 `CREATED` 订单，这个参数会让响应只剩 `{"id":"..."}`。成功时读取 `id`、`status`、`intent`、`purchase_units[0].amount`、`create_time`，并记录响应头 `Paypal-Debug-Id`。

最近交易：

```http
GET /v1/reporting/transactions?start_date={UTC}&end_date={UTC}&fields=all&page_size=20&page=1&balance_affecting_records_only=N
Authorization: Bearer {access_token}
```

日期跨度最多 31 天，时间格式 `YYYY-MM-DDTHH:mm:ssZ`。`balance_affecting_records_only=N` 才会带上不影响余额的记录。刚创建、尚未扣款的订单经常不在这个列表里。`paypal_reference_id_type` 为 `ODR` 时，`paypal_reference_id` 是订单号。代其他商家查 Transaction Search 需要合作伙伴资格；本次沙箱商家 token 已能返回历史交易。

沙箱创建测试订单时，每个 POST 使用新的 `PayPal-Request-Id`。PayPal 按这个值做幂等，最长保留约 45 天。拿到 `id` 后立刻再查一次。

## 8. 页面、安全和上线

1. 未登录时只显示授权按钮。
2. 回到 `/?auth=ok` 后展示商家身份，并自动拉最近 31 天交易。
3. 查询、创建测试订单都使用当前商家 token。
4. 退出时删除服务端的 refresh token。

安全要求：回调校验 `state`；不比对 token 响应里的 `nonce`；只请求当前环境的 `api-m.sandbox.paypal.com` 或 `api-m.paypal.com`，路径以 `/v1/` 或 `/v2/` 开头；本系统 POST 校验 `Origin`；日志不记录 authorization code、access token、refresh token 和 Client Secret。

上线时更换 Live 凭证和 `https` Return URL，授权主机改为 `https://www.paypal.com`，API 主机改为 `https://api-m.paypal.com`。用一个不是 App 所有者的真实商家完成授权，再用该商家的真实订单号查询。沙箱 payer_id 和订单号不能用于生产。

当前演示只有一个商家文件。接到业务系统时，按 `payer_id` 存多商家，refresh token 加密，access token 放缓存，查订单改为读取当前登录商家。
